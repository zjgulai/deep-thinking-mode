ReAct 推理行动链

Reason → Act → Observe 循环，用于需要与外部工具/环境交互的复杂任务

协议 URL：https://xmind.lute-tlz-dddd.top/combinations/react-agent-chain.html

01

组合定义

Reason → Act → Observe 循环，用于需要与外部工具/环境交互的复杂任务

02

适用问题

问题类型

  • 信息搜集+推理
  • 验证假设
  • 迭代求解
  • 工具调用规划

触发信号

  • 任务需要搜集信息然后推理，而非纯粹推理
  • 答案不确定，需要行动后观察结果再调整
  • 有多个可选工具/方法，需要动态选择
03

不适用与停止条件

以下边界直接来自已验证阶段的检查点与停止条件；任一阶段无法验证时，不应继续推进。

阶段检查点

  • 意图澄清（Intent Clarification）：苏格拉底式追问：在开始行动前，确认任务的真实意图。追问：1) 最终要得到什么？2) 成功的标准是什么？3) 有哪些已知约束？
  • 推理（Reason）：基于已知信息，推导：1) 什么信息/行动是必须的？2) 推断顺序是什么？3) 预期结果是什么？
  • 行动（Act）：执行第一个行动。行动前声明：1) 这一步的目标是什么？2) 使用什么工具/方法？3) 预期返回什么格式？
  • 观察（Observe）：分析行动结果：1) 结果是否符合预期？2) 发现了什么新信息？3) 需要修正计划吗？4) 是否满足停止条件？
  • 综合输出（Synthesize）：将所有观察和行动结果综合为最终答案。格式：结论→依据→局限边界→下一步建议。

阶段停止条件

  • 意图澄清（Intent Clarification）：任务目标和成功标准已被明确确认
  • 推理（Reason）：行动计划覆盖了所有必要步骤
  • 行动（Act）：行动已执行，有明确的输出（成功/失败/需要追问）
  • 观察（Observe）：任务完成 OR 达到最大迭代次数 OR 无法继续
  • 综合输出（Synthesize）：用户目标已被满足

站点规则：医疗、法律、财务或紧急风险问题须交由当地合格专业人士处理。

04

使用前需要提供的输入

输入合同按阶段顺序汇总全部唯一阶段输入；后续阶段可由前序输出交接补齐。

  • 意图澄清（Intent Clarification）：用户的原始任务描述
  • 推理（Reason）：来自 Phase 1 的结构化任务规范
  • 行动（Act）：来自 Phase 2 的行动计划，执行第 N 步
  • 观察（Observe）：来自 Phase 3 的行动结果
  • 综合输出（Synthesize）：所有历史 Reason-Act-Observe 记录

开始前请区分已知事实、仍待验证的假设和明确约束。

06

回退与循环

  • 观察（Observe） → 推理（Reason）
07

替代模型与替换边界

当前协议只发布经验证的稳定模型 ID。替换模型必须继续满足本阶段角色、输入、输出、检查点和停止条件，并重新通过交叉引用验证；不得按显示名称猜测替换。

09

事实、假设与专业升级

组合协议用于组织推理，不代表事实已经成立。每个阶段都要标记事实、假设与推断；医疗、法律、财务或紧急风险问题应交由当地合格专业人士处理。
