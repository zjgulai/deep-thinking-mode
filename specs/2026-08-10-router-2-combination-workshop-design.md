## 2. 现状、问题与证据

### 2.1 当前 Router 的真实能力

当前 Router 是浏览器本地的精确子串匹配器：

1. 对输入执行 `trim().toLowerCase()`。
2. 逐张路由卡读取空格分隔的关键词。
3. 只有当 `query.includes(keyword)` 时才加分。
4. 只要分数大于零，就把该问题类型视为命中。
5. 最多显示三个问题类型；没有真正的置信度、同义词、否定、多意图或语义理解。

生产复现中，包含“判断、根因、计划”的示例句能够命中三条路径；“迷茫，不知道下一步
怎么办”“比较利弊”“哪里出了问题”“讲不清重点”等六条自然表达全部进入空结果。
失败态要求用户“补充目标、约束或尝试”，但新增文本如果仍不包含预设短语，结果仍为零。

### 2.2 当前组合能力的真实状态

仓库已经存在三类相关数据，但尚未形成同一个产品能力：

| 数据 | 当前规模 | 真实作用 | 当前缺口 |
| --- | ---: | --- | --- |
| 问题类型 | 8 类 | 粗粒度意图入口 | 只支持精确短语 |
| Router 路由表 | 23 条 | 问题类型 × Agent 阶段 → 角色与模型 | 页面按问题类型聚合，阶段被抹平 |
| Chain 协议 | 5 条 | 有序阶段、输入输出、停止条件和复合 Prompt | 构建器不读取、不发布 |
| `chain_suggestion` | 13 条非空引用 | 从路由指向组合链 | 页面完全不显示 |
| 精选集合 | 6 组 | 按场景陈列若干单体模型 | 无顺序、交接或停止条件 |
| V3 模型 | 2789 个 | 单体模型定义、触发信号、协议和角色 | 只有少量模型进入 Router 引用 |

“精选集合”不是“组合链”。前者回答“这一场景有哪些模型可看”，后者必须回答“先用什么、
产生什么输出、如何交给下一步、何时停止或回退”。两者在页面中必须明确分区，不能混称。

### 2.3 信息架构缺口

当前 13 章负责知识主题分类，导航只有首页、模型库和 Agent 路由。组合能力不在任何章节、
没有独立页面，也没有从模型或章节反向进入组合的入口。用户无法发现仓库已有的五套链式协议。

## 3. 已冻结的产品决策

1. 保留现有 13 章，不新增第 14 章。
2. 新增一级产品能力“组合工坊”，与模型库、Agent 路由并列。
3. Router 继续在浏览器本地执行，不上传、不保存、不写 URL、storage、cookie 或远程服务。
4. Router 必须继续明确称为“本地规则导航”，不得称为 AI 判断或语义模型。
5. 低置信时只问一个最高价值澄清问题，不猜测模型，也不显示无操作的死空态。
6. 每次高置信匹配只推荐一个核心问题类型和最多两个辅助类型。
7. 每次只激活一条核心组合链；辅助类型补充模型，不并行拼接多条链。
8. Chain 使用稳定模型 ID 和角色 ID，不再依赖易重名的显示名称完成关联。
9. 五套现有 Chain 作为首版组合工坊的全部核心协议；不在首版开放用户自定义、保存或同步。
10. 六个精选集合保留为“主题精选”，不升级成伪组合链。
11. 不新增 npm dependency、远程 API、在线模型、数据库、账户或追踪。
12. 不为组合工坊新增历史导师或人物图片；它是跨章节工作台，不是新的知识章节。

## 4. 产品目标与非目标

### 4.1 用户目标

用户应能完成四条闭环：

1. 用自然语言描述问题，获得可解释的核心与辅助路径。
2. 在信息不足时，用一次点击或一次补充完成澄清，而不是反复撞空。
3. 从 Router 直接进入一条有顺序、有交接、有停止条件的模型组合。
4. 不输入问题也能在组合工坊浏览、理解并复制五条组合协议。

### 4.2 首版非目标

- 不建设聊天机器人或让网站直接执行组合链。
- 不调用在线 embedding、LLM、搜索、分析或风控服务。
- 不保存问题历史、自定义组合、收藏或用户画像。
- 不允许拖拽式无限画布和自由拼接 2789 个模型。
- 不自动把所有模型塞进组合；只有经过策展和验证的引用才能发布。
- 不改变模型的唯一主章节，不复制模型正文到“组合章节”。
- 不自动解决医疗、法律、财务、危机干预等高风险问题。

- 历史导师仍只代表章节策展身份，不被描述为组合协议作者。

## 6. Router 2.0 交互设计

### 6.1 输入区

首版保留一个多行文本框，不扩展为七字段长表单。输入区增加八个可键盘操作的意图快捷项：

- 找原因
- 做计划
- 做选择
- 想创新
- 做研究
- 做复盘
- 组织表达
- 澄清问题

快捷项是可选的真实 `button`，点击后提供明确输入，不直接伪造结果；用户可以继续补充文本。

输入区始终显示：

> 本地规则导航 · 输入不会上传或保存 · 结果需要结合事实验证

### 6.2 匹配状态

Router 只有五种互斥状态：

| 状态 | 条件 | 页面行为 |
| --- | --- | --- |
| `idle` | 未提交 | 显示示例和意图快捷项 |
| `needs_input` | 规范化后少于 2 个有效字符 | 要求补充，不滚动 |
| `matched` | 核心类型达到阈值且不存在并列歧义 | 显示核心、辅助和组合链 |
| `clarify` | 低分或第一、第二名过近 | 只问一个问题，并给 2–4 个可点击答案 |
| `safety_stop` | 命中明确高风险停止信号 | 显示边界和专业升级提示，不生成自助方案 |

状态文案不得再使用未经计算的“高置信”。所有状态通过可见文字与 `aria-live="polite"` 同步，
并且不只依赖颜色。

### 6.3 结果结构

`matched` 结果按稳定顺序呈现：

1. **问题理解**：显示识别的问题类型、阶段和仍缺少的信息。
2. **为什么这样匹配**：最多三个命中信号和一个相似示例，不显示内部调试分数。
3. **核心路径**：一个问题类型、核心角色和最多四个策展模型。
4. **辅助路径**：最多两个问题类型，每类最多两个模型。
5. **推荐组合**：一条核心 Chain 的有序阶段、输入、输出、停止条件和详情链接。
6. **下一步**：复制结构化提问，或进入组合工坊查看完整协议。

用户输入只通过 `textContent` 或表单值回显，不能进入 `innerHTML`、URL、日志或构建产物。

### 6.4 澄清恢复

`clarify` 状态不显示空白 ROUTE 框，而是显示一个最高价值问题，例如：

> 你现在最需要的是找出原因、做出选择，还是制定下一步行动？

规则：

- 每次只问一个问题。
- 提供 2–4 个按钮答案和“补充更多背景”入口。
- 用户选择后与原输入在内存中组合，重新匹配一次。
- 第二次仍不足时显示八类意图入口，不继续无限追问。
- 页面刷新、离开或清空后立即丢弃输入与选择。

### 6.5 高风险停止

匹配前先执行窄范围、显式信号的本地安全门。至少区分紧急人身危险、医疗诊疗、法律意见和
高风险财务决策。命中时：

- 不展示“已为你匹配解决方案”。
- 不把思维模型写成诊断、治疗、法律结论或投资指令。
- 说明网站只能帮助整理问题和准备向专业人士提供的信息。
- 紧急危险提示联系当地紧急服务和可信赖的人；不硬编码未经地域确认的电话号码。
- 允许用户进入“整理事实与问题清单”，但该路径必须保持边界文案。

## 7. 确定性本地匹配器

### 7.1 单一责任

匹配器只负责“将文本映射到策展问题类型和阶段”，不直接决定最终模型，不调用 Chain，也不
操作 DOM。DOM 控制器、构建编译器、数据验证器和匹配核心必须分离。

### 7.2 规范化

规范化依次执行：

1. JavaScript `NFKC`。
2. Unicode 小写化。
3. 将标点和连续空白折叠为单空格。
4. 保留中文、字母和数字；不做简繁转换，不引入分词依赖。
5. 同时保留无空格版本，用于中文短语和字符二元组匹配。

原输入只驻留内存；规范化结果不得持久化。

### 7.3 信号类型

每个问题类型维护以下互斥信号：

```json
{
  "id": "diagnosis",
  "label": "诊断根因",
  "positive_phrases": [{ "text": "哪里出了问题", "weight": 8 }],
  "negative_phrases": [{ "text": "不需要找原因", "weight": 10 }],
  "examples": ["产品数据突然变差，我想知道发生了什么"],
  "clarify_label": "我想找出原因"
}
```

权重只允许 1–10 的整数。同一归一化短语在同一类型中不得重复；正负信号不得相同。示例用于
低权重相似度补充，不能单独产生高置信结果。

### 7.4 评分

同一输入对每个问题类型计算：

```text
score = 正向精确短语权重之和
      - 有界否定作用域内命中的负向短语权重之和
      + 最佳示例二元组相似度奖励
      + 明确快捷意图奖励
```

约束：

- 每个正向短语只计一次。
- 只有负向短语使用有界否定作用域；正向、示例、快捷意图和安全信号继续使用各自既有规则。
- 负向规范化必须保留标点分句边界，普通空白可忽略；负向短语不得跨标点分句匹配，且不得改变公开 `normalizeRouterText()` 返回合同。
- 负向短语在同一分句内可精确命中，或按字符顺序作为 subsequence 命中；从首个匹配字符到末个匹配字符的总额外插入字符最多 4，限制是整条短语合计，不是每对相邻字符分别计算。
- 反转判断前只保留 inclusion-minimal 的最紧候选：若候选 A 严格包含候选 B，则丢弃 A；相同末端时丢弃起点更早的外层候选，防止 marker 中的字符被重新解释为负向短语起点。候选按起点升序生成，并以从右向左维护最小末端的线性扫描完成筛选。
- 若负向候选起点前的同一分句内存在 `不是`、`并非` 或 `并不是`，且 marker 末尾到候选起点之间最多 4 个字符，该候选视为双重否定反转，不计负分；marker 不得跨标点分句。
- 同一负向短语的最紧候选集合中，任一未被双重否定反转的有效候选即可让该短语计负分；每条负向短语仍最多计一次。
- 示例使用中文字符或字母数字二元组的 Jaccard，相似度低于 0.22 不计分。
- 示例奖励为 `floor(similarity × 6)`，最大 6 分，不能单独进入 `matched`。
- 用户点击快捷意图时为对应类型增加 8 分，并在解释区标明“你主动选择了该意图”。
- 完整公式计算后类型得分最低为 0。
- 排序固定为分数降序、策展优先级升序、类型 ID ASCII 升序。

### 7.5 置信与歧义

- `matched`：第一名至少 8 分，且至少有一个正向短语或快捷意图命中。
- `clarify`：第一名不足 8 分，或第一、第二名分差小于 2 且两者都至少 6 分。
- `matched` 时，分数至少 6 且与核心问题相关的第二、第三名可作为辅助路径。
- 得分为零时直接展示意图澄清问题，不显示伪候选。
- 阈值是公开可测试的产品规则，不在页面中显示为概率或百分比。

### 7.6 Agent 阶段

问题类型确定后，用独立阶段信号选择 `intent`、`cot_step`、`planning`、`execution`、
`reflect`、`tot_branch`、`research` 或 `synthesis`：

- 明确阶段信号命中时选择最高分阶段。
- 并列时使用 Router 数据中的稳定优先级。
- 没有阶段信号时使用 `intent`。
- 页面必须显示阶段名称，不能再把同问题类型的所有阶段无序合并。

### 7.7 模型与 Chain 解析

匹配器只返回 `{problemType, agentStage, evidence}`。构建时验证过的路由索引负责把它解析为：

- `recommended_roles`
- 稳定 `model_ids`
- 可空 `chain_id`

核心路由的 `chain_id` 成为唯一核心组合。若为空，结果页明确显示“当前没有已策展的完整组合”，
不借用其他阶段的 Chain。辅助路由只补充模型和角色，不同时启动第二条 Chain。

## 8. 组合工坊

### 8.1 总览页

总览页首先解释三类对象：

- 单体模型：一个认知工具。
- 主题精选：同一场景下值得浏览的模型集合。
- 组合协议：有顺序、交接、停止和回退条件的完整工作流。

随后只展示五条已验证 Chain：

1. CoT + Critic 求证链。
2. Tree of Thought 多路探索链。
3. Plan–Execute–Reflect 执行闭环。
4. ReAct 工具行动链。
5. Deep Research 深度研究链。

每张组合卡显示：适用问题、触发信号、阶段数、核心角色、循环或回退关系、预计输入完整度，
以及“查看协议”。不得显示虚构完成时长或成功率。

### 8.2 组合详情页

详情页按稳定顺序呈现：

1. 组合定义和适用问题。
2. 不适用与停止条件。
3. 使用前需要提供的输入。
4. 有序阶段时间线。
5. 每阶段的角色、主模型、输入、输出、检查点和停止条件。
6. 回退或循环关系。
7. 替代模型和替换边界。
8. 可复制的完整复合 Prompt。
9. 事实、假设、推断与专业升级提醒。

时间线用语义 `ol` 和文本连接，不依赖 SVG 关系图承载唯一信息。页面不执行 Chain，只提供
协议、链接和复制能力。

### 8.3 组合视觉语言

组合工坊沿用现有高明度暖纸、深墨正文和陶朱强调色，不新增导师图片。装饰职责保持 MECE：

- 纸条编号只表示阶段顺序。
- 细线只表示阶段交接。
- 回环标记只表示 `loop_back_to`。
- 风险和停止仍使用全站 Warning/Danger 组件。
- 章节色只出现在被引用模型的微型章节签名，不接管组合状态。

移动端时间线单列；打印保留完整协议和 URL，隐藏复制按钮与非必要装饰。

## 9. 数据合同

### 9.1 Router 索引 V2

`chain-protocols/agent-router-index.json` 升级为 `2.0-router`，成为问题类型、阶段信号和路由
关联的唯一权威。它必须包含：

- 问题类型的 label、priority、正向/负向短语、示例和澄清标签。
- Agent 阶段的 label、priority 和正向信号。
- 路由表中的稳定角色 ID、稳定模型 ID 和可空稳定 Chain ID。
- 单独的高风险信号表与停止类型。

不保留运行时 v1 fallback。迁移完成前构建失败，避免新旧字段静默混用。

`chain-protocols/agent-router-prompt.json` 同步升级为 `2.0-router-prompt`，继续提供可复制到
Codex 的完整路由提示词。它必须引用 V2 Router 的稳定问题类型、阶段、角色、模型和 Chain ID；
浏览器匹配结果只能来自结构化索引，不能解析这份自然语言 Prompt 反推路由。

### 9.2 Chain 协议 V2

五个 `chain-protocols/*-chain.json` 统一升级为 `2.0-agent-chain`。文件 stem 与 `id` 必须完全
相同；每条 Chain 至少包含：

```json
{
  "schema_version": "2.0-agent-chain",
  "id": "plan-execute-reflect-chain",
  "meta": {
    "name": "Plan–Execute–Reflect 执行闭环",
    "description": "...",
    "problem_type_ids": ["planning"],
    "trigger_signals": ["..."]
  },
  "input_contract": ["目标", "约束"],
  "anti_triggers": ["..."],
  "phases": [
    {
      "id": "goal-setting",
      "order": 1,
      "name": "目标设定",
      "agent_role": "planner",
      "model_ids": ["stable-model-id"],
      "input": "...",
      "output": "...",
      "checkpoint": "...",
      "stop_condition": "...",
      "loop_back_to": null
    }
  ],
  "codex_composite_prompt": "..."
}
```

同一 Chain 的阶段 ID、order 必须唯一；order 从 1 连续递增。`loop_back_to` 只能指向本 Chain
中序号更小的阶段。角色必须由 Router 声明，模型 ID 必须在 V3 中存在且声明该阶段角色。

### 9.3 主题精选

`knowledge/curated-collections.json` 继续作为精选集合权威。本功能实施结束前，全部模型关联必须
迁移为稳定模型 ID，并移除名称匹配 fallback。它不允许保存 phase、loop、handoff 或伪
`chain_id`。

### 9.4 构建就绪视图

数据加载器在全部验证通过后一次性返回只读、与源对象分离的构建视图：

```text
modelsById
problemTypes
agentStages
routesByProblemAndStage
chainsById
compositionsByModelId
compositionsByChapterId
safetySignals
```

构建器只消费该视图，不重新解析文件、不按名称猜模型、不为缺失 Chain 或模型静默降级。

## 10. 前端与构建边界

### 10.1 模块责任

- `tools/lib/v3-agent-data.mjs`：V3、Router、Chain 的公开安全加载和交叉引用验证。
- `tools/site-assets/router-engine.mjs`：唯一纯函数实现，负责规范化、评分、置信、歧义和阶段选择；
  Node 测试直接 import，构建时逐字节复制为浏览器本地资产。
- `tools/site-assets/router-controller.mjs`：只负责 Router DOM、状态、焦点和复制。
- `tools/build-site.mjs`：确定性渲染 Router、组合总览、组合详情和反向入口。
- `tools/site-assets/site.js`：保留全站导航、模型筛选和通用交互；移除旧 Router 匹配逻辑。

`router-controller.mjs` 必须通过相对路径 import `router-engine.mjs`；测试导入同一文件，不能
在测试与浏览器各复制一套评分规则。两者作为本地 ESM 发布，不使用 bundler 或新增 dependency。

### 10.2 页面数据

Router 所需的紧凑数据在构建时安全嵌入页面，不通过 `fetch` 加载。序列化必须转义 `<`、
`</script`、U+2028 和 U+2029。控制器只读取指定 JSON 节点的 `textContent`，解析失败时显示
“路由数据不可用”并停止，不回退到旧关键词逻辑。

数据预算：

- Router 嵌入数据不超过 96 KiB 未压缩。
- 不把 2789 个完整模型对象嵌入 Router；只包含已策展路由需要的 ID、标题、URL 和短定义。
- 组合详情由静态 HTML 承载，不在客户端加载全集。

### 10.3 确定性

- 不使用随机数、当前时间、对象未定义顺序或 locale-dependent 排序。
- 所有问题类型、阶段、Chain、模型引用和页面路径使用显式排序。
- 相同公开输入连续构建必须得到相同路径集合和逐文件 SHA-256。
- 构建在候选目录完成全部验证后，才整体替换 `site/`，随后逐字节同步 `docs/`。

## 11. 无障碍、响应式与隐私

- 输入有可见 label、说明和错误关联。
- 快捷意图和澄清选项使用真实 `button`，触控高度至少 44px。
- 匹配结果标题在用户提交后可接收程序焦点，但不打乱自然 DOM 阅读顺序。
- `aria-live="polite"` 只播报一次简短状态，不朗读整组结果。
- 所有核心/辅助、阶段、停止和风险状态同时有文字，不只靠颜色或位置。
- `prefers-reduced-motion: reduce` 下关闭平滑滚动和结果位移动效。
- 320px 无页面级横向滚动；组合阶段、模型链接和长 Prompt 自然换行。
- 200% zoom 后输入、澄清、结果和复制仍保持可达。
- 打印隐藏输入、快捷项和复制按钮，保留组合协议、停止条件和 URL。
- 输入、匹配中间值和选择不进入 URL、storage、cookie、analytics、控制台或错误上报。
- 页面离开、刷新、重置后不保留任何输入。

截图与测试日志只保存于被忽略的 `.local/reviews/router-2/`，不进入公开仓库和 Docker context。

## 12. 错误与失败边界

### 12.1 构建期阻断

以下任一情况使构建失败且不覆盖上一站点：

- Router/Chain schema 版本、字段、权重或 ID 无效。
- 问题类型、阶段、角色、模型、Chain、phase 或 loop 引用悬空。
- Chain 文件名与 ID 不一致。
- Chain 阶段序号不连续，或回退指向不存在/后续阶段。
- Chain 模型未声明阶段要求的 Agent 角色。
- Router 引用名称而非稳定模型 ID。
- 组合页面路径冲突、链接或锚点断裂。
- Router 嵌入数据超预算或不能安全序列化。
- 运行时引入外部资源、fetch、storage、危险 HTML 或内联事件。

### 12.2 客户端恢复

- 页面数据缺失或解析失败：显示明确不可用状态，不执行旧 fallback。
- 输入为空：保留输入区并聚焦，不滚动到结果。
- 低置信或歧义：进入一次澄清，不伪称匹配成功。
- 没有 Chain：仍显示核心模型，但明确说明尚无完整组合。
- 复制失败：选中完整 Prompt，并通过 `aria-live` 提示手动复制。
- 内部链接缺失：视为发布缺陷，由构建门阻断，不在客户端静默吞掉。

## 13. 测试与验收

### 13.1 黄金问题集

建立公开安全、无个人信息的 96 条固定问题集：

- 8 类问题 × 8 条不同口语/书面表达 = 64 条。
- 16 条多目标问题。
- 16 条低信息、歧义或高风险问题。

每条记录包含：输入、期望状态、核心问题类型、允许辅助类型、期望阶段、允许 Chain、禁止
高置信类型和解释信号。黄金集不只验证成功命中，也验证不得误匹配。

首版通过门：

- 64 条明确单意图问题 Top-1 准确率至少 85%。
- 16 条多目标问题的核心类型准确率至少 80%，且辅助类型不超过两个。
- 16 条低信息/歧义/高风险问题 100% 进入 `clarify` 或 `safety_stop`，不得伪装成高置信。
- 本次生产复现的 7 条问题全部进入正确匹配或澄清状态，不再出现死空态。

### 13.2 自动测试

至少覆盖：

1. Unicode 规范化、标点、大小写、中文短语和空输入。
2. 正向、负向、示例相似度、快捷意图和稳定排序。
3. 阈值、并列、辅助路径、阶段默认和多意图。
4. 风险停止优先于普通 Router。
5. Router/Chain V2 schema、稳定 ID、角色、模型和 loop 引用。
6. 五条 Chain 与 13 条非空建议全部解析。
7. 组合反向索引按模型和章节正确生成。
8. Router 页面嵌入数据、五种状态、澄清按钮、结果焦点和复制回退。
9. 组合总览、五个详情、模型与章节反向入口、面包屑和 sitemap。
10. CSP、零外部资源、零 fetch/storage、内部链接、UTF-8 和公开路径边界。
11. 连续两次构建路径和全部 bytes 相同。
12. `site/` 与 `docs/` 逐字节一致。

### 13.3 浏览器 E2E

视口至少覆盖 1440、1024、390 和 320：

- 七条复现问题逐条提交。
- 一条多意图问题展示核心、辅助与唯一核心 Chain。
- 一条歧义问题完成一次澄清。
- 一条安全停止问题不显示自助解决链。
- 五个组合详情的阶段、模型链接、停止条件和 Prompt 复制。
- 键盘完成输入、快捷意图、提交、澄清、结果、组合详情和复制。
- 页面刷新后输入为空；网络面板没有运行时外部请求。
- 控制台无 error 和未解释 warning。

### 13.4 发布验收

本地通过不等于生产完成。发布仍按以下独立门执行：

1. 全量 test/check/build/public/release 门。
2. 完整 `site/` 构件 hash 与 Docker allowlist。
3. 只替换既有 `xmind_site` 不可变镜像。
4. origin 健康与逐文件 bytes 验证。
5. 生产 Router 七条复现、组合详情、移动端与键盘 E2E。
6. 32 个既有域名前后严格 TLS、状态和目标无回归。
7. 保留上一镜像、审计目录和严格回滚点；不 prune。

## 14. 分批实施边界

实施计划应拆成四个可独立验证的批次：

### 批次 A：数据合同与纯匹配核心

- Router V2 schema、五条 Chain V2、稳定模型 ID、加载器和失败测试。
- 96 条黄金问题集与纯函数匹配器。
- 不修改页面，不生成站点。

### 批次 B：Router 2.0 页面

- DOM 控制器、五种状态、一次澄清、安全停止、结果解释与核心 Chain 入口。
- 移除旧 `query.includes` 逻辑。
- 定向 DOM/E2E 通过后再进入下一批。

### 批次 C：组合工坊与反向入口

- 总览、五个详情、首页预览、导航、章节和模型反向入口。
- 主题精选与组合协议明确分区。
- Sitemap、404、打印和移动端补齐。

### 批次 D：全量验证与生产发布

- 全量自动测试、确定性双构建、设计 QA、浏览器 E2E。
- 用户对本地候选签字后，才单独申请 commit/push/腾讯云替换授权。
- 生产逐文件、Router/组合 E2E、邻接域名回归和回滚证据完成后才验收。

批次失败只回到产生问题的最近模块；同类问题第三次验证仍失败时，停止叠加关键词或局部补丁，
审查信号合同、置信阈值、Chain 关系和页面状态架构。

## 15. 完成定义

只有同时满足以下条件，才能称为“Router 2.0 与组合工坊完成”：

- 13 章保持不变，组合工坊成为可发现的一级能力。
- 自然语言不再只靠精确关键词；低置信有一次可操作澄清。
- 页面不称 AI、不显示伪概率、不保存或上传输入。
- 8 类问题、8 个 Agent 阶段、23 条路由、5 条 Chain、13 条 Chain 建议和相关模型全部通过
  fail-closed 交叉引用验证。
- 五条组合协议公开可读、可复制、可由 Router 和模型/章节反向进入。
- 主题精选与有序组合概念清楚，不误导用户。
- 黄金问题集、自动测试、浏览器 E2E、确定性构建和公开构件门全部通过。
- 本地、Git、镜像、服务器 origin、生产域名和邻接应用分别保留证据。
- 生产失败可严格回到上一不可变镜像，且不污染其他 Docker 应用。
