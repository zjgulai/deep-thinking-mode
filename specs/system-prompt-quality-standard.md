# System Prompt 蒸馏质量标准 v1.0

## 1. 背景与目标

本标准定义思维模型 `codex_integration.system_prompt` 字段的合格门槛。

**核心原则**：system_prompt 是整个蒸馏系统的第一性产物。其唯一目的是——让 Codex 在接收到它之后，用该模型的推理方式重新组织思考，而不是只在名称上贴了个标签。

---

## 2. 四层必要结构

一个合格的 system_prompt 必须包含以下四层，缺任何一层即为不合格：

### 层 1：认知模式声明（Cognitive Mode Declaration）

> 我用什么视角和假设前提来看待这个问题？

- 说明该模型的**核心认知立场**（不是定义模型名称）
- 用第一人称或直接指令口吻
- 长度：1-3句，≤80字

❌ 不合格示例：`"请以第一性原理的方式思考。"`（等同于什么都没说）  
✅ 合格示例：`"拒绝从类比、惯例或他人做法出发。你的推理必须从可被独立验证的基础事实重建，一切假设须显式标注。"`

### 层 2：推理协议（Reasoning Protocol）

> 我具体按什么操作步骤走？

- 列出**可执行的具体动作**，而非描述模型功能
- 每步有明确的输入/输出
- 步骤数：3-6步

❌ 不合格示例：`"运用系统思维分析问题的各层次关联"`  
✅ 合格示例：
```
1. 画出变量清单：列出影响这个问题的所有关键变量（存量、流量）
2. 识别回路：标出哪些变量之间存在正反馈/负反馈
3. 找延迟：哪个环节的因果之间有时间差？这个延迟会怎样影响判断？
4. 定杠杆点：改变哪一个参数能对整个系统产生最大影响？
```

### 层 3：质量门禁（Quality Checkpoint）

> 每一步完成后我应该自我检验什么？

- 至少 1 条**判断标准**，让 Codex 能在推理中途自我校正
- 形式：自问句或 if/then 规则

❌ 不合格示例：`"确认理解了模型的核心逻辑"`（无法执行，无法判断）  
✅ 合格示例：`"每写下一个原因时自问：这是事实还是假设？假设有什么证据支撑？"`

### 层 4：输出格式约束（Output Format）

> 我的产出物应该是什么形状？

- 指定结构（列表/段落/表格/对比）
- 可选：指定最终结论的表达方式

❌ 不合格示例：（无此层）  
✅ 合格示例：`"输出格式：先列假设清单（打✗的是你删除的假设，打✓的是你保留的基础事实），再给重建后的结论。"`

## 3. 三维验收标准

完成蒸馏后，用以下三个测试验证 system_prompt 质量：

### 维度 A：保真度测试（Fidelity）

**方法**：把 system_prompt 交给不知道模型名字的人，让他描述"这个提示词让我用什么方式来思考问题？"

**通过标准**：他的描述能还原该模型的核心操作方法，且不会被误认为是其他模型。

**快速自测**：把 system_prompt 中的模型名字全部替换为"XXXX"，提示词是否仍然有意义且可执行？若无意义，说明保真度为 0。

### 维度 B：区分度测试（Differentiation）

**方法**：把两个相近模型的 system_prompt 并排放（如"第一性原理"和"5 Whys"），判断它们是否可以互换。

**通过标准**：两者的推理协议（层2）中至少有 2 个步骤是对方没有的。

**快速自测**：如果我把"第一性原理"的 system_prompt 用来分析一个流程优化问题，和用"5 Whys"的 system_prompt 会得到**结构不同**的回答吗？如果没有区别——蒸馏失败。

### 维度 C：激活度测试（Activation）

**方法**：用同一个真实问题，分别在"无 system_prompt"和"有 system_prompt"两种条件下问 Codex，对比输出结构。

**通过标准**：有 system_prompt 的输出应具备以下至少 2 个特征：
- 主动暴露假设
- 输出有可识别的步骤结构
- 结论有反常识的角度（不是常识性回答的重新包装）

---

## 4. 长度基准

| 模型类型 | system_prompt 字数下限 | 说明 |
|---|---|---|
| 分析类（5Whys、第一性原理、系统思维） | 150字 | 需要完整推理协议 |
| 认知状态类（决策瘫痪、框架思维） | 120字 | 需要触发条件+干预动作 |
| 行动类（WOOP、SOP、福格模型） | 100字 | 需要明确执行步骤 |

**当前基准**：大多数模型的 system_prompt 为 8-20 字。合格下限是 100 字，目标是 150-250 字。

## 5. 反例对照库（持续更新）

### 反例 1：同义反复型（最常见）
```
"请以决策心理学核心_启发式的方式思考这个问题。"
```
**问题**：用模型名字描述模型本身，信息量为零。

### 反例 2：功能描述型
```
"运用系统思维看清事物之间的关联和整体模式。"
```
**问题**：描述了模型能做什么，但没有告诉 Codex 怎么做。

### 反例 3：空洞励志型
```
"从整体视角出发，避免局部思维，找到系统的杠杆点。"
```
**问题**：语义上正确，但没有可操作的步骤，Codex 无法据此改变推理结构。

### 反例 4：伪步骤型
```
"1. 理解问题背景  2. 运用模型分析  3. 得出结论"
```
**问题**：步骤无实质内容，任何模型都可以套用。

## 6. 合格模板（以"第一性原理"为参考基准）

```
【认知模式】拒绝从类比、惯例或"别人都这样做"出发。你的推理必须从可被独立
验证的基础事实重建。一切假设须在推理过程中显式标注并接受质疑。

【推理协议】
1. 列出假设清单：把当前问题里所有"默认正确"的判断写成清单，逐条追问：
   这是客观事实，还是经验/惯例/他人做法？
2. 拆至公理层：对每条假设追问"为什么"直到触及不可再分的基础事实
   （物理约束、成本结构、人性需求等）。删除所有无法支撑的假设。
3. 从基础事实重建：只用上一步保留的事实，重新推导解决方案，不参考原方案。

【质量门禁】每写一个推论时，自问：这个推论能独立于现有惯例而成立吗？
如果答案是"别人都这么做"或"一直以来如此"——这不是理由，必须继续追问。

【输出格式】先输出「假设清单」（✗删除的假设 / ✓保留的基础事实），
再输出「从基础事实重建的结论」。最后标注：这个结论与常规做法有何不同。
```

---

## 7. 应用范围

本标准适用于：
- `knowledge/models-v3/*.json` 中 `codex_integration.system_prompt` 字段的人工审核
- `tools/upgrade-to-v3.mjs` 自动生成逻辑的设计约束
- 新增或更新模型时的质量门禁

**更新规则**：每发现 3 个新的典型反例，补充到第 5 节。
